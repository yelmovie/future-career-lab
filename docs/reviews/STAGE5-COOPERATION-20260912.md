# 스테이지 5 — 함께 살리는 숲 구현 기록

작성일: 2026-09-12 · 대상: 페이지 9의 스테이지 5 · 현재 작업 트리 기준

## 현재 기준

스테이지 5는 앞에서 얻은 드론 사진, 생태 조사, 돌봄 경험, 방송을 연결해 세 장소를 돕는 협업 체험이다. 이 문서와 현재 코드를 스테이지 5의 우선 기준으로 삼는다. 이전 문서의 강제 1인 실패, 12문항 릴레이, 다른 공원에 적용하는 마지막 시험은 변경 이력이며 현재 플레이 경로로 복구하지 않는다.

학생이 직업별 정보를 나누고, 자기 행동을 다음 팀이 이어 받아 현장을 바꾸는 과정을 이해하도록 구성했다. 이는 설계 의도이며 실제 학생의 이해도·학습효과·재미를 측정한 결과는 아니다.

## 바뀐 체험

| 이전 구성 | 현재 구성 |
|---|---|
| 혼자 출동할 직업을 먼저 고르고 정해진 실패를 봄 | 네 직업의 인물이 앞선 활동에서 가져온 정보를 소개하며 함께 출발 |
| 정해진 장소·직업 순서로 12개 선택 문제를 풂 | 지도에서 세 장소를 원하는 순서로 선택하고 서로 다른 조작을 수행 |
| 배지가 직접 말하는 인수인계 | 드론 전문가·생태연구가·사육사 하늘·방송기술자의 인물 그림과 역할 설명 |
| 반복 정답 선택 뒤 완료 | 묘목 심기·막힌 곳 표시·소리 조절 후, 다음 팀의 작업과 현장 결과를 확인 |
| 다른 공원 시험을 통과해야 마지막으로 진행 | 세 장소를 도운 뒤 전후 지도를 비교하고 수료증으로 이동 |

현재 흐름은 `팀 소개 → 지도에서 장소 선택 → 직접 활동 → 도움 전달 → 장소 결과 → 남은 장소 선택 → 함께 바꾼 숲 → 수료증`이다. 작업 중 지도에 돌아가 다른 장소를 먼저 도울 수 있으며, 이미 수행한 조작은 저장된 상태를 이어 쓴다.

## 세 장소의 조작과 완료 조건

| 장소 | 학생의 행동 | 접근 가능한 대안 | 다음 팀과 연결되는 결과 |
|---|---|---|---|
| 나무가 베인 곳 | 열매나무 묘목을 두 자리에 끌어 놓기 | 묘목과 자리를 차례로 누르기, 키보드 버튼 선택 | 위치·조사 정보를 바탕으로 심은 나무를 사람들이 계속 돌봄 |
| 막힌 물길 | 사진에서 자재가 모인 곳을 쓸어 표시하기 | 사진의 위치 표시 버튼 누르기, 키보드 버튼 선택 | 정확한 위치를 전달받은 정비팀이 자재를 치우고 돌봄 팀이 물가를 살핌 |
| 숲 옆 공사장 | 슬라이더로 공사 소리를 줄일 수준 정하기 | 기본 range 입력의 키보드 조작, 소리와 함께 보이는 상태 문구 | 방송 팀이 요청을 전하고 공사팀이 조용한 작업 방법을 적용 |

묘목은 두 자리 모두 심어야 하며, 물길은 위치 표시가 완료되어야 한다. 소리 조절은 실제로 슬라이더를 조작하고 값이 35 이하가 되어야 전달 버튼이 활성화된다. 세 장소의 완료 목록이 모두 채워져야 마지막 지도 비교로 진행한다. 정해진 오답이나 혼자 실패하는 장면을 강제로 거치지 않는다.

활동과 결과는 분리한다. 작업 화면에는 지금 할 일과 다른 팀이 이어서 할 일을, 결과 화면에는 전달 후 실제로 이어진 일을 보여 준다. 나무 성장과 현장 정비는 즉시 일어난 변화로 설명하지 않고, 돌봄·작업을 거친 시간 표기를 함께 둔다.

## 이전 저장 보존

새 활동 상태는 `pageData.p9Cooperation`의 `version: 1`로 저장한다. 전체 저장 파일을 초기화하거나 앞 스테이지의 사진·조사·돌봄·방송 기록을 지우지 않는다.

- 새 상태가 있으면 선택한 장소, 완료 목록, 심은 자리, 물길 표시, 소리 값과 조작 여부를 복원한다.
- 새 상태가 없으면 이전 `pageData.p9Alliance`에서 이미 끝낸 장소 수를 새 지도의 완료 목록으로 옮긴다. 진행 중이던 옛 퀴즈는 새 활동의 지도 선택으로 이어진다.
- 이전 `transfer` 단계는 세 장소를 도운 상태로 옮기며, 폐기한 다른 공원 시험을 다시 요구하지 않는다.
- 페이지 9를 이미 완료한 저장은 완료 상태를 유지해 마지막 비교 화면으로 들어간다. 기존 완료 기록을 지워 보상을 다시 받도록 하지 않는다.

위 항목은 구현된 복구 규칙의 설명이다. 가능한 모든 손상 저장 조합을 전수 검증했다는 뜻은 아니다.

집중 검사에서 버튼·슬라이더의 실제 조작 영역은 48px 이상이고, 가운데 창과 말풍선 사이 간격은 1024 화면에서 9.6px, 1728 화면에서 16.2px였다. 이 수치는 검사한 화면·상태에 한정한다.

작업 안내의 시제 분리, 지도 복귀 시 진행 단계 유지, 묘목 키보드 포커스 연결, 새 현장 결과 그림 적용을 완료했다. 작업 상단에는 실제 저장된 먹이나무·소음 비교 결과를 사용한다. 엔딩은 지도 자체를 직접 쓸어 비교할 수 있으며 하단 range·키보드 대안도 제공한다.

공통 다음 버튼은 드래그 직후 브라우저가 compatibility click을 생략하더라도 터치 pointerup에서 한 번 처리한다. 뒤따르는 click은 중복 실행하지 않는다. 수료증의 선택형 탐험 기록도 폐기한 공원 시험 대신 실제 `cooperation-help`·`alliance-clear` 기록을 보여 준다.

## 최종 통합 담당 기록란

- 최종 빌드: TypeScript 및 Vite production build PASS. 산출물 182파일·88,992,614바이트 무결성 검사 PASS. `test-results/stage5-final-build.log`.
- 단위·린트: 전체 단위 19파일 170개 PASS, 학습 기록 변경 후 관련 7개(신규 2개 포함) PASS. 전체 lint와 변경 파일 lint PASS.
- 기능 회귀: `stage5-final`에서 10개 E2E PASS(협업 4개, 기존 정원 드래그 2개, 방송 다시보기 2개, 완료 재방문·옛 경로 2개). 엔딩 직접 터치를 추가한 후 해당 태블릿 경로 재확인 PASS. 수료증 기록 연결까지 추가한 최종 `stage5-record-final`에서 협업 4개 다시 PASS.
- 전역 화면 경계: `e2e/layout-boundaries.spec.ts` 두 해상도 시나리오 PASS. `test-results/stage5-layout-regression/`에 주요 페이지·긴 문구·결과 상태 캡처와 경계 측정 보관.
- 후속 시각 검증: 작업 3종·물길/공사장 결과·엔딩 × 2해상도, 12상태 PASS(`final-update/report.json`). 마지막 소음 문구·range 높이 조정 후 소음/엔딩 × 2해상도, 4상태 모든 검사 영역 scrollX/Y 0, 잘림/겹침 0, range 최소 높이 48px PASS(`noise-output-report.json`, `ending-layout-report.json`).
- 자산 검사: 새 4장과 참조 위치·SHA-256을 manifest에 등록. 259개 미디어, 145개 실행 경로 자원 검사 PASS. 기존 원본·미사용 후보는 보존.
- 실제 학생 플레이·학교 기기 인수: 이 문서의 검증 범위에 포함하지 않음.

이 문서는 점수를 산정하거나 납품 준비도·학생 학습효과를 인증하지 않는다.
